## Retrieval and review

Up to three topic matches use named fields on the selected object and its upstream requirements, quality drivers and decisions. General constraints and shared neighbouring infrastructure cannot establish a local pattern need. Matching is lexical and handles simple explicit exclusions; it is not semantic inference. Request text may introduce an exploration topic, visibly labelled as a request rather than saved intent. If no specific topic matches, supported early chapters retain two explicitly generic boundary comparisons.

No prerequisite is automatically marked fulfilled. Exact triggering passages, the unassessed prerequisite status, risks, limits and receipts enter the inspected source packet and saved generation provenance. Current facts omit internal history snapshots from excerpts; full model basis remains the freshness check. Knowledge receives space before optional context under the existing excerpt budget. ## Verification and limits

- Twelve positive/negative retrieval fixtures cover a non-banking domain, explicit exclusions, audit trails and unrelated resource pools. Additional checks cover upstream quality evidence, shared-neighbour isolation and request-origin distinction.
- Compatibility checks retain original record hashes and accept older receipt shapes. Draft adoption preserves the exact matching rationale and risks, leaves model artefacts unchanged and rejects stale context.
- Existing Brain, LLM and Chapter 9 guided-design checks cover owner isolation, saved drafts versus accepted passages, failed saves, source review and frozen baselines.
- DOM integration exercises the focused diagram, recorded matching phrase, question preservation, no provider call while exploring/reviewing, full source packet, generated draft and saved knowledge provenance.
- The integration check caught knowledge being omitted behind large nested model snapshots; projection and source priority were corrected and the complete flow passed.
- Two live requests used only a synthetic equipment-reservation scenario. The first exposed a policy answer being forced into unrelated boundary alternatives. The second, after the server capability gate, returned zero options, cited the saved requirement and retry record, surfaced idempotency and bounded-retry prerequisites, and retained uncertainty about the timeout. The model was `gpt-4.1-mini-2025-04-14`; the second request used 3,939 input and 501 output tokens. This is a narrow grounding/behaviour check, not a broad architecture-quality benchmark. The response still favoured comparing retry mechanisms; deeper evaluation of simpler outcome-recovery alternatives remains necessary.
- The browser connection timed out during tab enumeration. No rendered desktop/mobile inspection was obtained. DOM checks do not establish visual layout quality.

The full repository is not live-connected. There are no embeddings, automated source refresh, release adoption/withdrawal workflows or calibrated pattern scores in this increment. These are explicit future work, not implied by the richer knowledge cards.
