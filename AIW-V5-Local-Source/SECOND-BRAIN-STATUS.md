# AIW Architecture Brain: governed second-brain status

This release extends the existing Mind Factory, Sol, Brain and canonical design graph. It does not create another design studio or give unreviewed repository text design authority.

## v20: the full knowledge repository, connected

The laptop's acquired corpus is now a knowledge repository service beside the workbench ([KNOWLEDGE-REPOSITORY.md](KNOWLEDGE-REPOSITORY.md)). It is no longer a 24-file pilot. The figures below were measured on the laptop from the 47 pinned snapshots:

| | Count |
|---|---|
| File entries | 186,219 |
| Documentation revisions | 18,961 (every byte verified, zero unavailable) |
| Body-indexed documents | 8,432 |
| Passages | 45,517 |
| Files that can become project sources | 7,753 |

Metadata-only dossiers are never text-indexed. Candidate and discovery-only repositories can be searched but not retrieved.

- **Mind Factory → Sources** searches the corpus, reads each passage from its verified original, and retrieves the exact original through `knowledge.fetch`. The source's identity is the same as a live GitHub read, so reviews, signed receipts and invalidations bind unchanged. *Interpret this passage* opens the claim form on its exact lines. The 24 pilot locators and the 56 sampled archive locators fold into an offline section while the repository is connected.
- **Revocation is automatic.** The service signs its revision and invalidation notices with a notices-only key (`AIW_REPOSITORY_NOTICE_KEYS`). That key cannot make a release receipt verify. A project with repository originals applies them when it is opened, through the existing signed-update path.
- **Live refresh.** `acquire` fetches newer documentation from approved repositories at an immutable commit. Downloads are checked against the git tree, credential-shaped files are quarantined, and the original acquisition root is never written. A rebuild turns the change into notices. `refresh.ps1` wraps it with a lock and logs. `register-refresh-task.ps1` registers a daily task; nothing registers it automatically. No live GitHub acquisition was run for this delivery.
- **Leads.** Beside what Sol will read, the workbench lists repository passages that mention what the decisions touch. They are marked *not sent to Sol*, and Sol never receives or cites them.

## Delivered workflow

1. Discover AKR's bounded public repository locators; retrieve up to five files sequentially at recorded commits, validate exact SHA-256, and save each original independently. Registered repositories also permit a chosen documentation path.
2. Find source-located passages. Suggestions and catalogue links are discovery material. Architects interpret exact excerpts with explicit conditions, limitations and polarity; reviewers verify original text and reuse rights.
3. Resolve recorded contradictions, freeze reviewed claims in a release, and activate that release for a project. Only eligible active claims enter the Architecture Brain, Sol's source packets and downstream receipts.
4. Explore a typed, read-only knowledge graph in Mind Factory: concepts, source revisions, passages, claims, contradictions, releases, organisation guidance, model rationale, pattern obligations, risks, prerequisites, component roles and interface roles. Its backlinks carry status and authority.
5. Check the current branch for a saved repository file. Unchanged text remains on the same source record. Changed text creates a successor revision and makes dependent released claims ineligible until reviewed and released again. Earlier text, decisions and SDD evidence remain available with changed-support warnings.
6. Brain retrieval traces directly named concepts and their declared alternatives, complements and conflicts, while keeping descriptive relationships separate from approved conditional claims. Semantic retrieval continues to index eligible claims and Playbook passages only.
7. The Windows knowledge-repository handoff adds 24 metadata-only pilot locators from two acquired repositories to the Sources view. A project editor can preview a newer candidate-only JSON packet in memory, with authenticated scope and hash-derived identity checks. An architect may explicitly retrieve a registered file through the existing immutable-commit/SHA-256 command, then interpret and review it. Packet preview neither stores originals nor imports claims, releases or change notices into project authority.
8. A separate signed repository update route accepts an Ed25519 receipt for an **existing**, exact project-reviewed release only when the source bytes, claim hashes, authenticated independent reviewer and project scope match. Repository claims cannot activate without an unexpired matching receipt. Signed contiguous revision notices advance the store cursor; signed invalidations withdraw matching saved source revisions, preserve earlier rationale and remove dependent claims from Brain retrieval. The Releases view downloads an unsigned signing request and accepts a signed update. No signing private key is stored in the Site.
9. Chapter 11 → Work → **Architecture case** selects 1–20 existing requirements, retains a starting point and scope history, and shows their actual linked objects across Chapters 2–10. It links back into Model, Sol and Mind Factory. Six review dimensions accept explicit architect observations with evidence references; changes to the design, scope or eligible support make earlier observations historical. Signed claims count only when linked to selected requirements or their traced objects. Case JSON exports include the basis, source locations, history and current gaps. Cases never confirm requirements, approve the design, or score quality.
10. Retained signed release proof is reverified against the current public key on project reads, exports, commands and LLM reasoning/adoption. Key removal or rotation, expired proof, changed scope and tampering fail closed. Legacy receipts without retained proof require a fresh signed renewal. The local server now accepts `AIW_REPOSITORY_SYNC_KEYS`; the Mind Factory Releases view shows readiness and missing human review.
11. A read-only SEABaaS evaluation harness measures source identity, requirement-to-chapter links, chapter findings, signed claim eligibility, and representative source cells. It does not invent design decisions or architect scores.

The project knowledge collection persists with the existing project in R2; no new storage silo or database migration was introduced. Organization guidance already has independent authenticated review and signed releases, and its installed entries now appear with source lineage in the graph.

## Signed pilot handoff

The project owner exports a signing request from **Mind Factory → Releases** for each independently reviewed repository release (or a withdrawal-only request). The laptop operator uses `scripts/prepare-repository-notices.mjs` to convert the candidate packet's complete contiguous cursor range into exact source-identity notices; it rejects notices whose original revision cannot be resolved. Run `scripts/sign-repository-sync.mjs keygen PRIVATE_KEY.pem` **on the laptop** once; keep the private key local and configure the returned key ID/public key in the Site setting `AIW_REPOSITORY_SYNC_KEYS` as a JSON map. Run `scripts/sign-repository-sync.mjs sign REQUEST.json PRIVATE_KEY.pem SIGNED.json STORE_UUID [NOTICES.json]` using the store ID from the local packet. Upload `SIGNED.json` in Releases. The signing request is bound to the authenticated project; no claim is created or independently reviewed by the signer. Install the public key and establish permitted source use before expecting any production guidance. Since v20 the local workbench applies the repository service's signed notices automatically; the hosted Site's automatic refresh and unattended delivery of release receipts are still outstanding.


## Running a focused case

Open Chapter 11 → Work → Architecture case. Select a representative requirement set and state the question being investigated. The object cards show actual links, including drafts; an empty stage may be a design gap or may not apply to that requirement. Follow a requirement in Model or discuss it in Sol and Mind Factory. Record observations against the exact current design and cite source passages, objects or measured results. AIW retains the starting point and every scope/observation revision. Whole-project chapter findings and formal SDD review remain separate from the selected case.

The case workflow and signing path are now usable; completing a real pilot still requires the architect's scope judgement, source rights review, independently authenticated claim review, laptop public key and signed release. A single-user local instance cannot manufacture a second authenticated reviewer. No synthetic test receipt or review is installed in a real project.
