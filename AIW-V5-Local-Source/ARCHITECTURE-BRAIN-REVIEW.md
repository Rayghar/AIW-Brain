# Grounded interaction design

## Product direction

AIW should connect a quality concern to architectural choices, concrete model changes and retained reasoning. This increment makes that path usable for one consequential question: complete an operation within the request, or accept work for durable queued processing. It is a focused foundation for deeper architectural judgement, not a complete pattern catalogue.

Mind Factory contains the comparison within the existing companion panel. Sol offers a contextual entry. The selected requirement and quality scenario remain visible. Two visual structures expose the changing roles; conditional quality effects, failure modes, verification questions and reconsideration conditions accompany them. Conditions and object composition are progressive steps. Saved comparisons reopen from the same surface. Ask Sol, Mind Factory and Cursor keep their distinct roles.

Preparing a comparison saves an alternative but leaves model records unchanged. The normal model impact review shows proposed responsibilities, new or reused application components, interactions, support capability, operating plan, trust boundary and a draft Chapter 3 decision. Acceptance applies the reviewed change atomically. The decision retains both approaches and a working selection; its formal acceptance remains separate. Original reasoning and source receipts accompany the working SDD and remain historical after later source review.

## Brain and model behaviour

- Explicit architect answers establish the completion contract, repeated-delivery protection, ordering, demand, owner, information authority, overload response, outcome discovery and recovery policy. Keyword similarity cannot satisfy these conditions. An immediate final-result requirement blocks the queued option; an unsafe repeated effect blocks it too.
- Both alternatives show conditional effects and verification obligations. No quality score, capacity figure, vendor, whole-system style adoption or verified performance claim is invented. Unknown demand or unresolved ownership stays visible.
- Reuse preserves selected component definitions while the proposal exposes new allocations and interactions. Existing routes remain; coexistence requires review. Selected object definitions, support needs, trust assignments, relationships, upstream intent and method receipts participate in freshness checks.
- Source changes block stale proposals. Review shows earlier and current intent and reused objects, records a conclusion, and retires outdated draft alternatives. Task revision and project revision checks prevent concurrent overwrites.
- The LLM packet includes the selected requirement and quality target before the typed reasoning projection. Explicit task identity prevents consulting a different saved comparison. Exact receipts and current/changed status survive generation and reviewed reuse. The existing 22-source / 28,000-character excerpt limits remain. This interaction flow cannot be converted into the older generic boundary proposal by the provider.
- The configured OpenAI integration and server-side secret are unchanged. The new flow is usable without an LLM. This release did not make a new live provider call.
