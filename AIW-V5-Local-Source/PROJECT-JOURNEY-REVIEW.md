# Project journeys and connected output

Reviewed 20 September 2026, following the persistent-control restoration.

## Delivered behaviour

- Private project home with search, saved revision/date, content counts, confirmation counts, resume, and chapter review entry points.
- A blank project starts without reference records. A Bank Payment Journey copy starts with clearly labelled illustrative records and unconfirmed numerical targets. Both use the same eleven chapter studios.
- Project identity is retained in navigation, API writes, chapter handoffs, exports, and contextual source links. Browser exploration settings and notes are scoped by project; legacy Bank Payment Journey preferences remain compatible.
- Empty later chapters offer first actions instead of crashing or reporting false completion. Empty interface, security, technology-realization, and runtime surfaces were exercised explicitly.
- User-authored journeys populate the process layer and simulated walkthrough. Blank-project logical ghosts derive from actual source requirements. Accepted ghosts retain edited wording, stable references, and their actual journey connection. Covered requirements lead back to the saved responsibility.
- A requirement edit exposes the linked records requiring review in Chapters 2–10. This is a trace-based review route, not a claim that every downstream record is automatically wrong. Existing source-change validation remains authoritative.
- Chapter 11 HTML includes a contents list, four model perspectives, real tables, complete model relationship registers, chapter registers, source status, open findings, and delivery obligations. Working and frozen outputs are distinct. New baselines capture the connected model with their source snapshot.
- SDD diagrams can scroll within their figure on narrow screens. Print output uses a separate A4 layout; the HTML contains no executable scripts or external assets.

## Practical boundaries

Guidance remains rule-based. Simulations illustrate the recorded design; they do not execute a bank, application, or infrastructure. Confirmation, architect acceptance, external governance evidence, and implementation verification remain separate states. Last-visited chapter and exploration preferences are browser-local; project records are saved privately on the server. This iteration makes no new concurrency or 100,000-user capacity claim.

Local QA projects are excluded from the deployment archive. Production project documents are not replaced by these fixtures.
