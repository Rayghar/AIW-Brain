# Round 20 · payment evidence journey and handoffs

## Product changes

- Chapter 11 cases can explicitly declare an **End-to-end evidence journey**. Existing focused cases retain their previous scope. The declared journey reads one selected requirement through a linked quality scenario, compared and recorded architecture decision, mapped application and technology, current named product comparison and selection, placement, and a current recorded test or exercise. Every selected requirement needs a model link. Its checklist opens the owning chapter and appears in the case dossier and Validate. An independent `support` conclusion for this mode is blocked until the recorded trail is complete; it remains a human judgement, separate from whole-project SDD approval and actual measured attainment.
- Validate now has addressable Readiness, Model integrity and Focused case lenses. A case deep link opens the case, and browser Back restores the prior reading. Focused case uses the full reading width so the worklist is not compressed by a redundant inspector.
- A new Chapter 6 capability saved from Application needs is immediately shown and focused in Capabilities, with its next support-and-rationale action. Chapter 7 leads an incomplete technology selection to the missing comparison or preference step before offering record/approval actions.
- A browser regression exercises the existing governed repository transfer with a synthetic original through project scoping, signature, rights confirmation, import and Design resources readback. It does not certify a real repository original.
