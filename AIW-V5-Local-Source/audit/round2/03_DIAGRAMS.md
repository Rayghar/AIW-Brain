## 1. Summary

1. Every chapter Model tab (1–10) opens on one standard-notation "Diagram" drawn by `notation-model.js` → `notation-layout.js` → `notation-view.js`; Chapter 11 has no Diagram although a 12th scene (`rationale`) is defined for it.
2. The notation is TOGAF-9 content-metamodel wording (Logical/Physical Application/Technology/Data Component) with 13 of 23 defined kinds ever drawn; actors, outcomes, business services, data entities and placements never appear.
3. Every relationship is drawn with the same solid line and the same filled arrowhead; "dashed" carries eight unrelated meanings; no cardinality; two labels ("is served by", "realizes") point against ArchiMate direction.
4. The Key says "Nothing drawn." for the elements of Chapters 1, 2 and 3 and lists flow words and contract references as "relationships".
5. Routing does what the README says it does not: on the reference project connectors cross elements 35 times and labels sit on boxes 35 times in Chapter 7; Chapter 6 has 49 crossings and 43 overlapping labels; on a 49-element project the grouped picture has 608 crossings, the tree is 6,234 px tall and the orthogonal picture 13,280 px wide.
6. Arrangements are single-sweep heuristics: longest-path ranking, one barycenter pass, no crossing minimisation, no channel assignment, groups laid out without regard to edges, "Swimlanes" degenerate on ten of twelve scenes, pins collide after the model changes, and the grouped layout depends on the window width.
7. The same object has four palettes and four vocabularies across the Diagram, the chapter's own map, the connected explorer, the anatomy and the SDD atlas; only the reference code (LR-001) is stable.
8. Interaction stops at select, hover, drag-pin, layers and export: no edge hover or selection, no focus/dissect/walk on the Diagram, no annotation, comment, diff, undo or keyboard move.
9. Document parity is absent: the SDD HTML draws its own ten "atlas" figures from a different model builder, the PDF and DOCX carry no figures, exports carry no hash manifest, the SVG export drops icons, refs, notes and the legend, overflows long titles, and uses 6.5 px kickers.
10. Exchange exports cover ArchiMate (8 types, all edges as Association, no views), Ilograph and Eraser (explorer perspective, not the scenes); no Structurizr, C4-PlantUML, Mermaid or draw.io, so no diagram leaves the tool as code.

## 4. Enrichment proposals (ranked by value ÷ effort)

Constraints honoured: no npm runtime dependencies (ELK/dagre cannot be imported; everything below is in-house ES modules), one canonical Design Graph (`architectureModel`), a position is never a fact, LLMs propose only.

**P1 · Relationship notation kit — S, closes D2-01/02/04/05.** Extend `edge()` with `ends`, `qualifier` and a `style` key derived from `kind`; add a `STYLES` table (`realizes`: dotted 2-2 + hollow triangle; `implements`/`implementedBy`: dotted + hollow; `servedBy` reversed as `serves`: solid + open V; `uses`/`flow`: dashed 6-3 + filled; `owns`/`exchanges` as access: dotted 1-3 + small open; `dependsOn`: solid, no head; `protects`/`mitigates`: solid green + dot; `threatens`: dashed red + filled; `path`: red numbered; `sequence`: solid + filled; module membership as nesting). Define six markers once in `<defs>` for screen and export. Rebuild `legendHTML()` from the drawn `KINDS` and `STYLES` (BPMN symbols included) and emit the same Key group in `svgString()`. Fix the two reversed directions. Effort 1–2 days, all in `notation-model.js`, `notation-view.js`, `notation.css`, plus a test that every drawn `kind` has a style and a Key row.

**P2 · In-house layered layout with corridor routing — L, closes D2-11/12/13/14.** Replace `rank/order/rowsToPositions/route` with a Sugiyama pipeline in `notation-layout.js` (~700 lines, no dependencies): (1) cycle removal by DFS back-edge reversal (exists); (2) rank assignment by longest path then iterative balancing of ranks toward the median of neighbours (a cheap network-simplex substitute) with a width bound that wraps a rank into two rows when it exceeds the page width; (3) dummy nodes for long edges; (4) eight alternating median/barycenter sweeps plus adjacent transposition, stopping when crossings stop falling; (5) x-coordinates by the priority method (Sander) or a Brandes–Köpf pass, groups as compound nodes laid out recursively (inner layered layout, outer layered layout of group boxes, which also fixes `grouped`); (6) orthogonal routing on the channel grid between ranks with a channel-assignment pass that gives parallel runs distinct offsets and bundles a parent's fan-out; (7) label placement by scanning the two longest runs for a free slot against nodes, groups and other labels. Determinism is kept (sorted inputs, no randomness); a 300-element synthetic fixture targets < 500 ms and asserts 0 through-passes, monotone crossing reduction and page bounds. Radial and lanes remain as they are but lanes is restricted to scenes with lane groups.

**P3 · SDD figure parity and artifact manifest — M, closes D2-17/28/29 (C-12).** Move `svgString()` into a DOM-free `notation-svg.js` that takes `(D, L, {key: true, notes: true, pageWidth})` and is the only renderer for screen export, the SDD HTML, and (via a rasteriser-free path) the PDF: for PDF, write the SVG primitives (rect, path, text with the embedded DejaVu font already in `review-pdf.js`) as a PDF content stream — no image XObject needed.
