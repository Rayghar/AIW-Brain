# AIW V5 Live Model Explorer: frontend code audit

**Scope.** Browser code in `AIW-V5-Local-Source/public/` (index.html, entry.js, app.js, 207 JS modules, 40 CSS files), plus the parts of `server.js`, `build.mjs` and `worker.js` that decide how the frontend is delivered.

**Source identity.** The extracted copy matches `origin/release/aiw-v0.10.0-rc.10.73.6-standard-diagrams` at commit `3ee0854` (`git archive` compared with `diff -rq`, excluding `node_modules` and `.aiw-local`). No source file was modified.

**Method.**
- Static reading and grep, plus my own import-graph script.
- Dynamic checks ran on an isolated copy at `scratchpad/v5-agent-frontend`, with its own server on port 4291 and its own SQLite file.
- The shared server on port 4173 was used once, read-only: only GET requests to the existing `bank-payment` project, with every non-GET API request aborted. Its project stayed at revision 1.
- Browser: Playwright with headless Chromium build 1194.
- Line references are relative to `AIW-V5-Local-Source`.

## 1. Architecture map

```
index.html ── 40 <link rel=stylesheet> (all chapters' CSS, every page) + <script type=module src=entry.js>
   │
entry.js  (routes on ?view / ?chapter; entry.js:3-13; statically imports knowledge-ui.js + logical-domain.js)

                (app.js:80,89,90,93); Model tab still draws legacy SVG graph (app.js:76,97-115)
                ─► workspace-ux.js refineWorkspace (workspace-ux.js:194): post-render DOM patching
                   (refineProject 480-497, foundationPanels 286-316, pagination 324) and lazy chapter
                   models via CHAPTER_MODELS (workspace-ux.js:152):

                      (projections), *-layout.js, notation-view.js + notation-model.js (standard

                      architecture-explorer.js (am-*)
Shared domain: 19 *-domain.js files, also copied into the Worker (build.mjs:18): commands, findings, exports
Persistence:   project-store.js: GET /api/project, POST /api/commands {revision, command}; response =
               whole document (worker.js:157); aiw:save / aiw:external-project events trigger full re-render
Sol / LLM:     intelligence-ui.js (Ask Sol: prepare → packet → generate → adopt), brain-reasoning-ui.js
               (Sol rounds), chapter-sol.js (companion), stewardship-ui.js; change review in

Build:         build.mjs copies public/ → dist/client, embeds every public file as a string in
               dist/server/assets.js (8.6 MB); no bundling, minification, hashing or compression
```

Composition in one sentence: chapters 1–3 are separate page apps. Chapters 4–11 share one shell (app.js) that switches the active studio through a Proxy and then hands the Model tab to a lazily imported chapter model. That chapter model is laid over the still-rendered legacy canvas, which is hidden with CSS.

Routing uses the query string only. The parameters are `chapter`, `tab`, `object`, `model`, `view`, `project`, and the deep-link keys `decision`, `driver`, `artefact` and `focus`. `app.js:26-38` validates the values against allow-lists, and the URL is only ever updated with `history.replaceState`.

## 4. Strengths worth keeping (verified)

- **LLM output always waits for a human action.**
  - *Ask Sol* runs prepare → show packet → generate (sent with `packetStamp`) → an explicit *adopt* button (`public/intelligence-ui.js:61-69`).
  - Sol rounds re-prepare the packet when the question changes, "so what is sent is what was shown" (`public/brain-reasoning-ui.js:82-95`).
  - Adopting challenges or architecture answers requires `reviewed===true` (`public/intelligence-context.js:158`, `public/architecture-drafting.js:40`, `public/brain-authoring.js:25-33`).
  - Sol refinements and proposed threats go through the change-review dialog, with an "I reviewed…" checkbox and *Apply*/*Keep as alternative* buttons (`public/chapter-sol.js:129-160`, `public/workbench-ui.js:30-36`).
  - The stewards' capture, release and activate actions open forms with an empty reviewer and reason (`public/stewardship-ui.js:82-97`).
  - I found no path that applies an LLM response on arrival.
- **LLM text is escaped when rendered.** In `intelligence-ui.js`, `brain-reasoning-ui.js`, `chapter-sol.js` and `stewardship-ui.js`, only counts are inserted raw.
- **No provider key in the browser.** `OPENAI_API_KEY` appears only in setup help text (`public/intelligence-ui.js:25`, `public/brain-reasoning-ui.js:147`, `public/desk-view.js:353`), and every call goes through `/api/intelligence/*`.
- **Free-text fields are escaped, and so is the newer code.**
  - 1,023 hostile free-text markers and a hostile project name executed nowhere across 44 chapter/tab pages and Projects; the only exception is the enum-backed `effect`.
  - The v20.x chapter-model and diagram views (model-stage, notation) escaped every probe value.
- **Commands are the only way the model changes.**
  - The store sends a revision with every command (`public/project-store.js:5-11`).
  - Pattern search found no direct writes to the shared document.
  - A 409 keeps the user's input and offers a reload.
- **Domain validators on the command path** check enums and URL schemes (`public/decisions-domain.js:74`, `public/technology-domain.js:142,158`, `public/security-domain.js:44`, `public/interfaces-domain.js:63`, `public/technology-realisation-domain.js:49`).
- **Accessibility foundations are in place.**
  - Native `<dialog>.showModal()` in 19 files, a skip link and a polite toast live region (`public/index.html:46`).
  - 19 `aria-live` and 96 `role=status/alert` uses, 588 `aria-label`s and 72 `:focus-visible` rules.
  - Beyond contrast and nested-interactive, axe found no rule failures.
- **Heavy assets load lazily.**
  - `vendor-docx.js` and `review-font.js` load only through a dynamic import in `review-documents.js`.
  - Chapter models load on demand (`public/workspace-ux.js:152`) behind a "Preparing the Chapter N model…" placeholder (`public/workspace-ux.js:156`).
- **CSS class prefixes isolate the modules.** Only 106 of 7,254 selectors are styled in more than one file.
- **The local server is careful.** It guards against path traversal (`server.js:22`), revalidates with ETags (`server.js:23-25`), binds to loopback by default (`server.js:11`), and query parameters are checked against allow-lists (`public/app.js:26-38`).
- **The workbook parser is bounded** (`public/workbook-reader.js:3`, `WORKBOOK_LIMITS`).
- **The suites I ran all pass:** 25 unit and 7 browser.

## 5. Not verified

- How the hosting platform serves `dist/client` (routing, compression, caching). Only the packaged Worker's embedded asset handler was exercised (F-21).
- Rendering of hostile HTML returned by a live or mocked LLM. The LLM renderers were reviewed statically only.
- The `javascript:` `sourceUrl` click path in Chapter 7 options (F-01): automation could not reach the option panel, so this is based on reading the code.
- Other import routes (organisation releases, knowledge packs, model exchange) were not tested for the same validation bypass. `feedback.import` goes through validated assurance commands.
- Real-device CPU and real-network behaviour. The figures come from a container CPU over loopback, with CDP throttling.
- Screen-reader behaviour, touch and mobile interaction, and zoom/reflow beyond what the passing suites assert.
- The remaining ~70 validation suites, including 14 other browser suites. `test:browser` was deliberately not run (F-26).
- Server-side authorisation, CSRF and the rate limits of the API routes (backend scope).
- Vulnerability status of the vendored packages (no network SCA was run), and licence status of the bundled knowledge content (the catalogue and SA Playbook text).
