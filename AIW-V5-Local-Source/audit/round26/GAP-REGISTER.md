# Round 26 · Gap register — the Work, Model, Validate and Output tabs, Chapters 1 to 11

Baseline: AIW v0.10.0-rc.10.73.26 (commit c3d0289). Controlling baseline AIW v0.10.0-rc.10.73.6.
Target: AIW v0.10.0-rc.10.73.27.

How the gaps were found. Five read-only reviews of the release at the baseline: one code map of the four tab frames
across the eleven chapters (`uniformity-matrix`, `standardisation-notes`, `features-to-keep`), and four browser
reviews from a user's seat (1440 × 900, light theme, no language model connected) on the Bank Payment Journey reference
project and on a blank project: Chapters 1–3 (G1), 4–6 (G2), 7–8 (G3), 9–11 (G4). Each reviewer walked every tab,
pressed every control, read every dialog, and wrote per-tab findings with screenshots. Nothing was saved except
"Run checks" (which records a check run) and, in Chapter 2, the priority arrows pressed by a walker (they save on
click: that is itself a finding). The reviewers did not read the owner's register or any client material.

Carried into this register: the round-8 journey audit items still open (J-22, J-23, J-25, J-26, J-31, J-42, J-43,
J-44, J-53) and the round-12 gap-register items GR-UX-09 to GR-UX-17.

Severity: **major** = a user is misled, blocked, or loses trust (wrong numbers, dead or silent controls, a record they
never chose, a document they cannot see); **minor** = friction, wording, layout.

Columns: the decision (D-26-xx, in PLAN.md) that fixes it and the workstream (W1–W5) that carries it; "acceptance" names
the suite that will pin the fix. Source ids are the reviewers' finding ids (G1-1-work-2 = reviewer G1, Chapter 1, Work,
finding 2) and the framework notes (F-M2 = standardisation-notes §1.1 row M2).
