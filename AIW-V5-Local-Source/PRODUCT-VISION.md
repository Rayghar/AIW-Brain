# AIW V5: the product we are building

AIW is one living architecture workbench. The existing application is the product; new work must deepen its continuous journey, not introduce a competing studio or a disconnected set of chapter applications.

## The experience to preserve

1. One project and stable object identities from requirements to the operating architecture and SDD. Re-entering the same information in a later chapter is a defect to resolve.
2. Always show the current chapter and surface, the selected context, what comes next, and meaningful readiness. Exploring a screen is not evidence of completed architecture.
3. Preserve Work, Model, Validate and Output. Each is a way of working on the same project, not its own copy of the data.
4. The same live model reveals process, logical and physical application, data, technology, interfaces, security and deployment. Selection, rationale and relationships should remain understandable as the view changes.
5. Cursor explains the actual object, attributes, relationships and gaps. Mind Factory explores patterns, alternatives, tactics and anti-patterns. Sol helps perform the current task. All three remain separate and chapter/tab-aware.
6. Model changes are understandable, editable proposals before acceptance. Reference examples, assumptions, working choices, architect acceptance and governance approval stay distinct. No hidden winner, invented target or automatic approval.
7. Flows and failure scenarios explain the design and remain labelled simulations. They do not imply connection to a bank or evidence of measured operational performance.
8. A living SDD carries the design, rationale, evidence, unresolved obligations and change history. Frozen baselines remain fixed.
9. Retain the original forest-green, paper and muted-gold direction and interaction controls. Reduce scrolling with bounded panels, progressive disclosure, an uninterrupted chapter list and a separately scrollable perspectives section; do not remove capability to make a cleaner screenshot.
10. Private by default. No public deployment without explicit user approval.
11. Co-design and co-authoring are capabilities of working with AIW. They must not displace Ask Sol, Mind Factory or Cursor with another set of top-level modes. Improve how the existing companions help the architect perform a task.

## The continuous chapter journey

## The AIW Brain

Every decision in AIW is meant to go through one loop. The instruments read the design. The knowledge repository recalls what is known about it, with receipts. Sol, the LLM, reasons over both and advises. The architect decides through the chapter's change review. The outcome is recorded for the SDD and for the knowledge stewards. The loop is in place on the review desk, for every drafted fix, judgement, switch point and decision. It is also in place in every chapter model's companion, Chapters 2 to 10, for the record the architect has selected, a *What if* move, a part seen from Chapter 9, and a round of the chapter's records with the most open checks. The loop also learns. A disagreement with Sol goes to the knowledge stewards, and Sol advises them. What they capture is reviewed, released and linked to its record, and from then on Sol reads it with that record. See [AIW-BRAIN-ARCHITECTURE.md](AIW-BRAIN-ARCHITECTURE.md).

## Shared Architecture Brain integration

The Explorer now carries the recovered knowledge authority contracts through one graph and retrieval service. The complete 328-record descriptive catalogue and 30 repository registrations are available for exploration; 327 exact Playbook passages carry source identity into reasoning. Project sources become typed conditional claims through explicit passage review, contradiction handling, release freezing and project activation. Existing project sources can be reused without re-entering them. Repository acquisition resolves immutable revisions and stores exact originals, without promoting them automatically.

Sol, Mind Factory and Cursor share eligible support for the selected object. Mind Factory visualises concept roles and alternatives; the source and release lifecycle stays within that companion. Graph and text retrieval remain available without an LLM. Optional semantic retrieval uses the existing OpenAI connection and a private index with exact content, release and embedding-model identity. The reviewed source packet, Brain engine/policy, provider, citations and interpretation remain inspectable.

Reviewed claim links travel into composition and original model/SDD receipts. Withdrawal invalidates affected support and pending proposals while retaining history. Newly applied model proposals have a reviewed reversal when later work can be preserved. These mechanisms have passed domain, server and mounted-interface acceptance, with real provider and repository connectivity checks. See `BRAIN-INTEGRATION-REGISTER.md` for the actual evidence and remaining independent review and rendered-browser gates.

Product direction: use this shared foundation to deepen source-backed architectural judgement and evaluate it across independent project domains. Extend composition recipes only when their conditions, trade-offs, object changes and verification obligations can be defended. A larger catalogue is not a substitute for that evidence.


## Composition and quantitative evidence

Mind Factory now joins seven architectural concerns into one comparison flow: interaction, reads, persistence, publication, resilience, distribution and structure. Eight new executable alternatives connect styles, patterns and tactics to responsibilities, components, interfaces, support, operating obligations and the working decision. The comparison retains simpler alternatives and blocks incompatible conditions before a model can be prepared. Transactional outbox is now a concrete proposal with a single commit boundary, retained intent, relay and protected downstream effects.

Quality effects now have an explicit calculation and observation path. The architect can supply workload quantities, inspect formulas and compare alternatives, then record sourced measurements against the exact design. Estimates never establish achieved targets. Stale evidence remains visible and traceable. Sol uses the same method packet, checks candidate explanations against it, and returns structured method findings when a generated explanation fails that check. The second provider pass is an automated guard, not independent certification.

See `BRAIN-COMPLETION-REGISTER.md` for the completed software scope, acceptance evidence, browser infrastructure blocker and external validation that must still be earned. The governing direction remains: make architectural judgement visible in the model, preserve the architect's acceptance authority, and earn confidence through measured evidence rather than catalogue size or generated certainty.
