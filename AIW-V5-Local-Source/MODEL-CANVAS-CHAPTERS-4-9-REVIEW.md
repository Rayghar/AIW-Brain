# AIW modelling walkthrough: Chapters 4–9

23 September 2026 · Bank Payment Journey reference project · Working architecture

## What was walked

I used the supervised browser preview of the Site checkout at a desktop viewport of approximately 1363 × 936. Starting with **Settlement hub** in Chapter 4, I followed each chapter’s green forward action through Chapter 9, observed the rendered canvas and accessible control tree, opened object details, exercised keyboard move and resize, Smart arrange, Release placement, zoom and the generative cursor. I compared the same banking payment model in each chapter. The reference records are illustrative, pending review; this walkthrough does not establish production architecture or verified control operation.

The owner-private deployed Site requires ChatGPT sign-in. The browser’s automatic approval review rejected a direct sign-in click because that action must use its validated authentication flow, which does not accept this single-link sign-in page. I therefore used the supported internal Site preview for visual interaction, and checked the deployable build separately. **This is not a signed-in browser verification of the private deployment.**

## Canvas interaction pass

- **Move and resize:** Focused a move handle and pressed ArrowRight; the selected Audit trail moved to the next 8-pixel grid position. Pressing ArrowLeft on the resize handle reduced its width. I also dragged the Chapter 8 contract’s move and resize handles: its x position changed from 413 to 432 and its width from 268 to 288; Smart arrange preserved both changes. Collision and architectural-group checks kept the cards in their lanes. A move had rounded the original card width due to a second bounds pass; I fixed that so changing position preserves the initial size.
- **Smart arrange:** Reflowed the view around the held Audit trail and verified its selected placement and reduced width remained. The arrangement now stores only deliberately held cards and calculates the other cards from the current view. Opening Details no longer changes the underlying world width; closing it restores the same spatial layout. Release placement removes that anchor and returns it to automatic arrangement. Reset placement restores the default chapter view. These are personal view operations, not architecture changes.
- **Zoom and orientation:** At the original Chapter 4 layout, Fit entire view made labels too small; the revised horizontal path is readable at 100%. Fit selected object, 1:1, pan and zoom remain available for larger views. The canvas guide is now attached to the model content region rather than the scrolling world, so its legend and “select to follow” hint remain visible while scrolling.
- **Details and cursor:** The Audit trail detail pane shows its Illustrative status, definition, all four underlying control relationships, and a separate Release placement action when held. A hover over the control showed the generative cursor asking what happens at its protects relationship and pointed to selection and Sol. The cursor is contextual guidance, not a change to the model or proof of reasoning quality.
- **Saved perspective and baseline:** Automated model checks cover chapter identity, manual occurrence sizes, saved perspective content, frozen-source reading and SDD linkage. Automatic approval review rejected opening “Save this perspective” in the preview because it classified that click as persisting non-trivial application state without explicit authorization. I did not attempt an indirect route; visual save/reopen and a signed-in deployment trial remain unverified.

## Judgment against the AIW vision

The resulting journey has a useful **locate → realize → support → choose → exchange → protect** rhythm. It preserves the banking payment subject while changing the *question* and *subset* at each chapter. The strongest improvements from this review are the compact Chapter 4 path, the focused Chapter 9 protection cross-section, and stable user-held arrangements. The canvas now avoids the most obvious ball-of-yarn failure in this example, while Explore still permits the full connected topology when needed.

The modelling capability is not complete. I would do the following next, in this order:

1. **Explain a selected connection in place.** Display direction, underlying record, ownership, coverage, evidence state and unresolved obligation beside the clicked edge. The current detailed records exist but require a separate pane and an expert’s interpretation.
2. **Reveal shared context one step at a time.** From Service connectivity, show one selected consumer and summarize the others, with a clear return to the followed worker and camera. Do the same when a control protects several contracts.
3. **Put uncertainty where the architect looks.** Show “product not selected”, “provider confirmation needed”, “timeout/duplicate response unagreed” and “control not verified” on the affected object or link, with the specific owner and evidence request. Avoid presenting an intended control as assured protection.
4. **Trace one payment outcome across the same model.** Bring the process path, information authority, external contract, pending outcome, enquiry and recovery owner into an ordered reading attached to these objects. This is the next step toward the surgeon-style cross-section.
5. **Run observed novice and practitioner sessions.** Test whether someone unfamiliar can locate Settlement hub, distinguish view placement from editing the model, explain the contract and trust boundary, recover from a wrong turn, and read the canvas on compact and touch screens. Then perform an actual Orbus import/update; existing export tests use a synthetic target mapping.

The SEABaaS case is a separate requirements-backed sample. Its workbook-derived topology remains hypothetical pending independent review. This banking payment walkthrough improves AIW’s modelling experience; it does not certify SEABaaS claims, Architecture Brain recommendations or an enterprise repository integration.
