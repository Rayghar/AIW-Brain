# rc.10.72.1 Implementation and Self-Audit

## 1. Audit objective

The implementation was compared with rc.10.72.0 to determine whether it replaced conflicting ownership or merely overlaid more CSS and handlers.

The comparison excludes installed dependencies, Playwright traces/reports, transient test output and current-release screenshots.

| Measure | rc.10.72.0 → rc.10.72.1 |
|---|---:|
| Baseline files compared | 3,153 |
| Current files compared | 3,160 |
| Added files | 41 |
| Removed files | 34 |
| Changed files | 56 |

The removed entries are primarily obsolete hashed production assets regenerated by Vite. The important source delta is the addition of a standalone layout service, its tests, a single navigation owner stylesheet, a structural gate and a focused browser journey.

## 2. Non-patch assessment

### Canvas

The layout capability is not implemented as DOM translation after rendering. `smartCanvasLayout.ts` receives canonical architecture nodes and edges and returns deterministic positions and compound dimensions. The stage studio applies the result through the existing presentation mutation boundary and keeps an undo snapshot.

### Navigation

The release introduces `aiw-journey-nav-v2` with explicit state. Active geometry no longer depends on hover, focus or `:has()` selectors. The v2 stylesheet is imported last and legacy selectors are removed from active ownership. The shell grid uses one navigation width variable and zero gap.

### Lifecycle and Brain context

The lifecycle service now accepts the explicit active lifecycle step. The next-move calculation does not force users backward merely because upstream warnings remain. Architecture Brain context is taken from the active project/stage/scope/revision rather than an inherited default workspace.

### Viewbook

The navigation handoff uses a durable pending-open state and mounts the actual Viewbook component. A browser assertion prevents SDD and Viewbook destinations from silently resolving to the same page again.

## 3. What was deliberately not changed

- Architecture object semantics and relationship meaning.
- The single server-side Architecture Brain authority.
- The signed AKR-0.10.72.0 knowledge release.
- Requirements, Journey Atlas and System Context governance.
- Human acceptance before canonical model mutation.

## 4. Regression findings

The focused rc.10.72.1 laptop acceptance passed. The inherited rc.10.66/rc.10.67 laptop files did not complete under the aggregate Playwright harness in this environment; their desktop tests passed 4/4, and the new laptop arrangement/navigation journey passed. This is recorded as a harness/regression-coverage limitation rather than represented as a full inherited laptop pass.

The complete combined inherited suite also showed non-terminating behaviour when several files were executed in one command. Executing Architecture Genesis and Brain Authority separately per viewport completed successfully. Release evidence therefore records the actual execution pattern instead of claiming one aggregate command passed.

## 5. Self-audit verdict

**Verdict: structural replacement passed.**

The release adds model-aware arrangement as a domain-informed presentation service and establishes one navigation geometry owner. It does not rely on a blanket `overflow-x: hidden`, hover width override or a second independent canvas state.
