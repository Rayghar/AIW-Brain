# rc.10.72.2 Product Recovery Comparison

## Comparison scope

The recovery compared the clearest pre-fragmentation product baselines—rc.10.70.1 and rc.10.71.0—with the stronger but increasingly layered rc.10.71.1, rc.10.72.0 and rc.10.72.1 implementations.

## What was preserved

- Canonical Architecture Model and revision boundary;
- one server-side Architecture Brain Orchestrator;
- Requirements Intelligence and source/evidence records;
- Journey Atlas and System Context;
- Architecture Context Graph and semantic lineage;
- Pattern DNA and governed Architecture Knowledge Release;
- deterministic eligibility and validation;
- optional governed LLM enrichment;
- preview, explicit acceptance, audit and rollback;
- smart canvas arrangement;
- signed knowledge and benchmark evidence from rc.10.72.0.

## What was removed from the active experience

- separate visible Stage Co-Author identity;
- separate normal-workflow Architecture Brain identity;
- Brain Signal cards as a competing recommendation surface;
- embedded intelligence panels that permanently occupied canvas space;
- duplicate guided-delivery rails and stage-navigation ownership;
- automatic System Context candidate regeneration after acceptance;
- false-authority quality-style recommendations;
- long repeated Review disposition controls;
- UI contracts that forced obsolete product identities to remain active.

## Source comparison

The working-tree comparison against rc.10.72.1 records:

- **102 changed tracked files**;
- **4,908 inserted lines**;
- **14,380 removed lines**.

The net deletion is intentional. Recovery required removing overlapping paths rather than placing another facade over them.

## Non-patch assessment

The recovery qualifies as structural rather than patch-based because it:

1. removes obsolete user-facing identities;
2. changes the Brain request contract to preserve exact lifecycle semantics;
3. changes context assembly, not merely response wording;
4. establishes a new shared Sol workspace component;
5. removes previous active UI tests that would force obsolete identities back into the code;
6. rebuilds Review and navigation ownership;
7. deletes substantially more code than it adds;
8. verifies the new product grammar through clean-project browser journeys.
