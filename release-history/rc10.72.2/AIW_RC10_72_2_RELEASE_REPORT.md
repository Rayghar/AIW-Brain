# AIW v0.10.0-rc.10.72.2 Release Report

## Release identity

- **Release:** AIW v0.10.0-rc.10.72.2
- **Name:** Product Recovery and Unified Sol Experience
- **Codename:** Sol One Experience
- **Controlling knowledge release:** AKR-0.10.72.0
- **Acceptance class:** Product recovery verified; external production acceptance blocked
- **Production accepted:** No

## Why this release exists

The product had accumulated several technically valid but overlapping experiences: Stage Co-Author, Ask Sol, Architecture Brain, Brain Signals, embedded intelligence cards, Living Canvas actions, output rationale and multiple navigation/lifecycle systems. The backend intelligence authority had improved, but the user experience no longer felt like one product.

rc.10.72.2 is a recovery release. It retains the canonical model, Architecture Brain Orchestrator, Requirements Intelligence, Journey Atlas, System Context, Pattern DNA, governed knowledge and reversible mutation boundaries, while removing competing user-facing intelligence identities and restoring one comprehensible architect journey.

## Controlling product grammar

The normal lifecycle experience is now:

**Work → Output → Validate → Stage plan**

Sol is exposed through one contextual workspace with three modes:

- **Draft:** fill or improve structured stage information;
- **Design:** propose the next governed model change on the canvas;
- **Ask:** explain, challenge or compare.

The user no longer has to understand the internal distinction between the Kernel, Brain Signals, Stage Co-Author, Co-Architect and Living Canvas orchestration.

## Principal structural changes

### Exact lifecycle semantics

Requirements, Quality Drivers and System Context are now preserved as distinct lifecycle stages in the Brain request contract. They are no longer collapsed into Logical Application before reasoning. Sol receives the exact project, stage, scope and revision.

### Stage-specific Brain context

Ask Sol now assembles a bounded evidence package relevant to the active stage, including accepted requirements, measurable drivers, journeys, selected scope, neighbouring objects, relationships, interfaces, decisions, findings, open questions and the matching Architecture Context package. It no longer depends on a broad undifferentiated project dump.

### One visible Sol experience

The stage shell contains one Sol entry point. Draft, Design and Ask are modes of the same drawer. The canvas contains one compact Sol Design surface. Legacy Brain Signals and embedded intelligence panels are removed from the normal modelling experience.

### Navigation recovery

The application uses one primary role journey rail with explicit expanded, collapsed and responsive-overlay states. Labels are left aligned. Hover does not change rail width or workspace geometry. The duplicate lifecycle rail and legacy navigation selectors are removed.

### Canvas recovery

The canvas remains the main work surface. Smart, tree, radial and grid arrangements remain available, but competing side panels no longer permanently cover the model. Sol Design presents a small ranked action set, with preview and explicit acceptance through the existing governed mutation boundary.

### Review recovery

Review & Assurance is reorganised into Summary, Findings, Decisions, Evidence and Governance lenses. Findings use a queue/detail/disposition model instead of repeating actions throughout a long report page.

### Quality-driver authority correction

A style ranking is not presented as authoritative until the project contains at least one prioritised driver and one measurable quality scenario. Before then, the UI clearly labels the ranking as provisional.

### System Context canonical-state correction

Accepting a System Context no longer triggers automatic candidate regeneration on the next project revision. Canonical context remains visible until the architect deliberately asks to revise it.

### Knowledge-receipt correction

All Brain receipts now default to the currently promoted knowledge release, **AKR-0.10.72.0**, rather than the older reference release.

## Clean-project proof

A new project was created from a short agency-banking idea and progressed through:

1. Requirements generation and acceptance;
2. Journey Atlas;
3. System Context generation and acceptance;
4. Logical Application proposal and acceptance;
5. Application Realisation proposal and acceptance;
6. Logical Technology proposal and acceptance;
7. Physical Technology proposal and acceptance;
8. Review & Assurance;
9. SDD & Delivery Pack.

The accepted modelling changes created a small but coherent lineage chain from Payment Domain and Payment Processing Service through an event worker, a provider-neutral messaging capability and a physical product/deployment topology. The SDD correctly remained locked because an approval baseline had not been completed.

This proves product continuity and governance. It does **not** prove that the resulting small model is a complete production agency-banking architecture.

## Retired UI contracts

Six old browser suites asserted superseded user-interface identities such as a separate Stage Co-Author drawer, a separate Architecture Brain launcher and previous navigation class names. They are retained in release history for auditability but removed from the active suite. Their useful behavioural intent is covered by the three rc.10.72.2 replacement suites.

## Release boundary

This release restores product coherence; it does not finish every AIW programme objective. External enterprise trust, live-provider quality, large-model performance, broad accessibility/browser acceptance, fully calibrated domain architecture generation and human expert validation remain mandatory future gates.
